# Give Together: your coding roadmap

The app's idea is yours. The current implementation, Google integration, and these starter files were written by Codex. Keep that distinction clear in your submission.

## Start here: two small Python exercises

Open `student_features.py` in your editor. Search for **YOUR TURN**.

| Place to write code | What you control | Skills to practice |
| --- | --- | --- |
| `donation_ideas(category)` | The homepage's “What could I give?” suggestions | Strings, lists, `if`, `elif`, `else` |
| `progress_message(percent)` | The encouraging sentence on drive cards | Numbers, comparisons, `if` statements |

The functions have basic AI-written defaults so the website still works. Replace their logic yourself. I can explain errors or give hints without supplying the finished solution.

### First mission

Make `donation_ideas("Food")` and `donation_ideas("Toys")` return different useful lists. Ask a food pantry or drive organizer which items they accept. Decide what should happen with an unfamiliar category too.

1. Change the function and save the file.
2. Open a terminal in the Give Together folder and run `python student_features.py` (or `py student_features.py` on Windows).
3. Refresh the website.
4. Click **Donation ideas** at the bottom of the homepage and change the category in **What could I give?**. Those suggestions now come from your Python code.

No extra Python packages are needed. The Python script writes a small JSON file; the browser reads that file. It is not a Python web server. Changes appear only after you run the script again and refresh.

### Second mission

Write encouraging messages for 0%, 1–49%, 50–99%, and 100% progress. Before running your code, predict the answer for 0, 1, 49, 50, 99, and 100. These are useful boundary tests: they catch mistakes at the edges of your conditions.

You can try your functions in a Python terminal:

```python
from student_features import donation_ideas, progress_message
print(donation_ideas("Food"))
print(progress_message(50))
```

Use `assert` to check the results against messages and lists that YOU chose. Record a bug you found and how you fixed it.

## Next: a substantial feature you own

The small exercises above are a starting point, not a guarantee of enough original work for the competition. Pick a larger feature to design, implement, test, and explain yourself. My recommendation is **an item-needs tracker**:

- Organizers enter specific items and how many they need.
- Donors choose an item and quantity.
- Your code calculates how many are still needed.
- Handle someone canceling and someone bringing only part of what they promised.
- Show the remaining needs on the drive page.

Start the calculation in Python using lists and dictionaries. Sketch your data and write test examples before building the screen. We can then work through connecting YOUR calculation to the app. This would change the app's real behavior, rather than just its colors or wording.

Other meaningful options: a packing-box calculator, a category-and-budget donation recommender, or your own reminder eligibility rules. Choose one and build it in small steps.

## Where the rest of the app lives

- `public/index.html`: page structure and headings.
- `public/style.css`: colors, spacing, and buttons.
- `public/app.js`: drive cards and button behavior, written in JavaScript.
- `server.mjs`: sign-ups, access checks, and SQLite storage, written in JavaScript.
- `google-auth.mjs` and `public/google-signin.js`: Google sign-in. Leave the security checks in place while learning.
- `test.mjs`: automated Google-auth and donation-workflow checks.
