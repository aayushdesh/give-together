# Give Together

![Give Together website screenshot](docs/give-together-screenshot.png)

Small acts. Shared impact.

Give Together helps people start donation drives, find drives to join, and report when they drop off their donations. Organizers can confirm deliveries and track needed items.

This student project runs locally with Google sign-in, a SQLite database, and Python features for donation ideas, progress messages, item counts, and daily encouragement. The screenshot shows sample activity for a presentation.

## Open the website

1. Install Node.js version 24 or newer if needed.
2. Double-click `START.bat` on Windows and keep the window open. On the first run, it downloads Google's official sign-in library.
3. Visit **http://localhost:3000** in Chrome or Edge.

On other computers, run `npm install` once, then `npm start` from this folder.

## Connect Google (one-time setup)

Open **http://localhost:3000/google-setup.html** for the step-by-step setup guide, or open `public/google-setup.html` from this folder. Follow it with a trusted adult.

You will create a Google web Client ID, allow `http://localhost` and `http://localhost:3000`, and paste the ID into a `.env` file copied from `.env.example`. No client secret is needed. Restart the server afterward.

Until this is done, everyone can browse, but nobody can sign in, create drives, or join them. The site shows a clear setup message. A real Google sign-in could not be tested without your own configured Client ID; automated tests check signed-token verification with local test keys.

After connecting Google, click **Join with Google**, then choose a nickname. The same Google account signs you back in next time. We save its stable identifier, not its Google name, email, photo, or password. Google may require approval for supervised or school accounts. Sign-in does not verify a person's age or prove that an adult is supervising.

Old password sign-in is disabled. Earlier local records remain in the database, but Google accounts are separate. They are never automatically linked by name or email.

## Use the app

1. Click **Start a drive** and describe what to collect, where to drop it off, and the end date.
2. People join and say what they plan to bring.
3. The organizer opens **Checklist** and checks **Received** when items arrive.
4. **My giving** shows drives you joined. **My drives** shows drives you created. You can switch reminders off or leave a drive you joined.

Reminders appear in the app. Optional browser notifications run at most once daily per pending drive while the site is open and the donor is signed in. There are no closed-browser alerts, emails, or texts. Reminders stop after receipt, opting out, leaving, or the drive ending.

## Write your own Python code

Start with **YOUR-CODING-ROADMAP.md**, then open **student_features.py**. Its functions control donation suggestions, progress messages, and remaining item counts on the real site. **greetings.py** supplies the daily encouraging quote.

Run `python student_features.py` after changes, then refresh the website. Open **Donation ideas** at the bottom of the page to see your suggestions. No extra Python packages are required.

This is an AI-generated starter project. Use **MY_BUILD_LOG.md** to document the code you write and the help you use. The roadmap links to the official Congressional App Challenge rules and explains why small starter edits alone should not be presented as creating the entire app.

## Storage and limits

Data is stored in `data/give-together.sqlite`. Closing and reopening the site keeps it. Only a drive's organizer can view its complete checklist or check off donations. Use a nickname and avoid adding contact details to free-text fields.

The app runs on this computer only. It is not a published or moderated platform for children. Before inviting children online, work with an adult organizer on hosting, HTTPS, account access, moderation, privacy, supervision, and the relevant service requirements. Plan actual drop-offs at school or community locations with a trusted adult.

## Test donors for your checklist

Six fictional donors are available in two clearly labeled practice drives: Community Food Drive and Share a Little Joy. Each has six sign-ups, with a mix of received and pending donations. Sign in with your own Google account, open My drives, and choose Checklist on a practice drive.

These are database sample people, not Google accounts you can sign into. They have no login credentials or sessions, and reminders are disabled. Real drives are not changed. Practice records contribute to the dashboard totals; they are not real-world impact.

To seed a fresh local database after your first Google sign-in, run `node seed-test-data.mjs`. Running it again does not duplicate records or reset your checkmarks. ### Checking donation choices
The signup form and server check each donation against that drive's **What to bring** list. Separate organizer items with commas. Donors can use the item buttons or type the same wording, optionally with a numeric quantity (for example, `3 bags of rice` when `rice` is listed). Capitalization does not matter. Multiple items can be separated with commas or “and”. An unlisted item displays “Please bring…” and prevents signup until corrected, including when mixed with an accepted item. Rejected entries are not saved as signups.

This is a simple list check, not AI: it does not recognize synonyms or guess misspellings. Conditions such as “unopened” remain part of the accepted wording. The check uses What to bring, independently of item tracker totals. Existing signups are unchanged.

Browser code: edit public/app-main.js and public/donation-check.js, then run npm.cmd run build. npm.cmd start also rebuilds public/app.js automatically. The generated file includes the item checker so the signup form does not depend on a separate script request.


### Donation center directory
The Donation centers section searches exact five-digit U.S. ZIP codes and filters by Nonprofit or City program. It is a growing local directory, not a nationwide live search or distance-radius search. The starter coverage is 94403 (Samaritan House), 94402 (San Mateo Main Library), and 94070 (Second Harvest Bing Center). Official donation pages are linked on the cards. Source checks were performed October 18, 2026; always confirm current hours and accepted items with the organization.

Signed-in users with nicknames can add public center details for any ZIP code using Add a center. These entries are labeled Community listing — not verified; no affiliation or nonprofit status is certified by this form. Entries persist in the donation_centers table in the existing SQLite database. The directory stores no search history or precise user location. Its search works offline once the app is running; external organization links require internet access. All listings are shared only by people accessing this app instance; this local app is not published online.

The starter records live in donation-centers.json. On startup, centers.mjs inserts missing starter records without deleting existing listings. New starter data does not overwrite previously saved records. The browser UI is public/centers-ui.js, included by build-client.mjs. Restart the server after adding or changing API code: Ctrl+C, then npm.cmd start. Refresh the browser afterward.

Explore drives is a single-page directory with three exclusive groups in order: New to you, You’ve joined, and Created by you. Ownership takes priority if an organizer also signed up. Each group has a count, and signed-in cards show a relationship label. Search, category, and Include ended drives apply to all three groups. Navigation scrolls to the groups. Older /?page=explore links also load the complete single-page interface.

Daily quote: greetings.py supplies positive_message(). The AI-written daily_quote_bridge.py and daily-quote.mjs expose GET /api/daily-quote. The browser shows it under the main heading and checks every minute while visible, and when returning to the tab. Quotes use the server computer’s local date. Repeats across days are possible. If Python fails, a fixed encouraging message stays visible. Restart Node after installing this server change; editing your messages afterward only requires a refresh.

Donors can report a drop-off from View details and undo it until receipt is confirmed. Reports persist as signups.reported_at. Reminders pause while awaiting confirmation. Organizers see a count on their cards and reports first in their checklist, with timestamps. Only organizer confirmation counts as received. Item totals remain separate. This is an in-app status, not an email or text notification. Cards refresh automatically each minute; reopen the checklist to get its latest reports.
